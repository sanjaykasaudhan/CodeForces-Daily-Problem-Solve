🚀 Codeforces Problem Solved: Subset Mex

I recently solved Problem A — Subset Mex from Codeforces Round 670 (Div. 2).
This problem is a great example of how frequency counting + greedy observation can simplify a problem involving sets and MEX.

🔗Problem Link: https://lnkd.in/ghwgaJ2q

🧠 Problem Idea
We are given a multiset of integers and need to split its elements into two subsets A and B.
The goal is to maximize:
mex(A) + mex(B)
where mex is the smallest non-negative integer that does not exist in the set.
For example:
mex({0, 1, 3}) = 2
because 0 and 1 exist, but 2 does not.

💡 Key Observation
To make the MEX of a subset equal to k, that subset must contain:
0, 1, 2, ..., k-1
Therefore:
For the first subset, every number from 0 upward needs to appear at least once.
For the second subset, every number from 0 upward needs to appear at least twice overall, because one copy may be used by the first subset and another by the second.
So we only need to count the frequency of every number.

🔢 Step 1: Count Frequencies
The code uses:
freq = [0] * 102

for x in arr:
 freq[x] += 1
For example, if:
arr = [0, 2, 1, 5, 0, 1]
the relevant frequencies are:
0 → 2
1 → 2
2 → 1
3 → 0

🔍 Step 2: Find the First MEX
We start from 0 and continue while every number exists at least once:
mex1 = 0

while freq[mex1] > 0:
 mex1 += 1
So if:
freq[0] > 0
freq[1] > 0
freq[2] > 0
freq[3] = 0
then:
mex1 = 3

🔍 Step 3: Find the Second MEX
For the second subset, every number from 0 upward must have at least two copies available:
mex2 = 0

while freq[mex2] >= 2:
 mex2 += 1
If:
freq[0] = 2
freq[1] = 2
freq[2] = 1
then:
mex2 = 2
Therefore:
answer = mex1 + mex2

🔍 Example
Consider:
arr = [0, 0, 1, 1, 2]
Frequencies:
0 → 2
1 → 2
2 → 1
3 → 0
For the first subset:
0, 1, 2
are all available, so:
mex1 = 3
For the second subset:
0 and 1
each have two copies, but 2 has only one copy.
Therefore:
mex2 = 2
Final answer:
3 + 2 = 5

⏱️ Complexity
Let n be the number of elements.
Building the frequency array → O(n)
Finding mex1 → O(n) in the worst case
Finding mex2 → O(n) in the worst case
Therefore:
Time Complexity: O(n)
Space Complexity: O(n)

🎯 Key Takeaway
When splitting elements into multiple groups, frequency counts can tell us exactly how many groups can contain each required value.
For MEX:
1 copy → supports one subset
2 copies → supports two subsets
So instead of actually constructing the two subsets, we can directly calculate their maximum possible MEX values using frequencies.
