🛠️ The Approach 
The problem requires us to calculate a running total where the operation alternates between addition and subtraction for each sequential element. 
Fast I/O amp; Parsing: I utilized sys.stdin.read().split() to pull the entire dataset into memory instantly, bypassing standard Python I/O delays. The State Toggle: Instead of using modulo arithmetic on the loop index (if i % 2 == 0), I initialized a simple multiplier sign = 1. 
Linear Accumulation: I looped through the n elements, adding the current value multiplied by our state flag to the accumulator: p += sign * int(input_data[idx + i]). 
The Flip: At the end of each iteration, I instantly flipped the operation for the next element by multiplying the state by negative one: sign *= -1. 
Batch Output: The final accumulated value p is converted to a string, appended to the out array, and efficiently flushed via sys.stdout.write using a newline join. 

⏱️ Complexity Analysis
Time Complexity: O(N) per testcase. The logic requires a single, rapid linear scan through the array elements, executing basic arithmetic operations. Across t test cases, it scales optimally as O(ΣN). 
Space/Memory Complexity: O(N) auxiliary space per testcase. Memory is required strictly to buffer the parsed input stream and to compile the output strings before writing them to standard output.
